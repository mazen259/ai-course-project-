# BFS — Problem Formulation & Animation

تطبيق تعليمي ببايثون وStreamlit لتنفيذ **Breadth-First Search فقط**، مع صياغة المسألة وعرض الخطوات بأنيميشن. جميع الوصلات موجّهة وتكلفة كل وصلة تساوي 1.

[قراءة الشرح بصيغة PDF](BFS_Problem_Formulation.pdf)

## التشغيل

تحتاج Python 3.11 أو أحدث. افتح الطرفية داخل مجلد المشروع بعد فك الضغط، ثم نفّذ:

```bash
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

افتح العنوان الذي يظهر في الطرفية، وغالبًا يكون `http://localhost:8501`. يحتاج تثبيت Streamlit اتصال إنترنت في أول مرة؛ العرض والرسم لا يعتمدان على خدمات أو مكتبات خارجية على الويب.

## استخدام الواجهة

1. اختر مثالًا من القائمة الجانبية وحدد البداية والهدف وترتيب الجيران.
2. اضغط «تشغيل» لتبدأ المحاكاة، أو استخدم «التالية» و«السابقة» وشريط الخطوات.
3. تابع الطابور من الأمام إلى الخلف، وترتيب الزيارة والمسار الحالي. الحل يظهر باللون الأخضر عند خروج الهدف من الطابور.
4. افتح تبويب **Problem Formulation** لمراجعة العناصر الستة وتجربة الحركات وGoal test.
5. افتح **Time & Space** للتمييز بين التعقيد النظري ومقاييس التجربة، وبين تكلفة BFS وتكلفة حفظ الأنيميشن.
6. جدول الخطوات قابل للتنزيل بصيغة CSV، وكود BFS قابل للتنزيل من الواجهة.
7. أسفل الشريط الجانبي تجد تنزيل التقرير PDF والمشروع كاملًا ZIP.

في مثال الجراف المحلول:

```text
Visit order: A → B → C → E → F → G → D → H
Solution:    A → C → F → H
Path cost:   3
Peak queue:  3
```

## تعديل الجراف

اختر «جراف مخصص · JSON»، واكتب قاموسًا مفاتيحه الحالات وقيمه قوائم الجيران:

```json
{
  "S": ["A", "B"],
  "A": ["G"],
  "B": [],
  "G": []
}
```

وجود `"S": ["A"]` يعني وصلة من S إلى A فقط. لتمثيل اتجاهين أضف كل حالة إلى قائمة جيران الأخرى. أضف الحالات الطرفية بقوائم فارغة. يقبل التطبيق الدورات والوصلات الذاتية والحالات المنفصلة، ويمنع تكرار دخول الحالات للطابور. الحد 30 حالة و120 وصلة لإبقاء التتبع والرسم مناسبين للتعلّم؛ الجرافات الصغيرة أوضح بصريًا.

## الملفات

- `bfs.py`: صياغة المسألة، Search Node، BFS، وسجل الخطوات. يعمل مستقلًا عن Streamlit.
- `bfs_simple.py`: نسخة قصيرة للقراءة أولًا، تستخدم الصياغة نفسها وتعيد الحل وترتيب الزيارة بدون سجل العرض.
- `examples.py`: الجراف المحلول، شجرة السكشن، ومثال المدن.
- `visuals.py`: رسم SVG من غير مكتبات رسم إضافية.
- `app.py`: الواجهة والتحكم في الأنيميشن.
- `.streamlit/config.toml`: ألوان الواجهة وإعداداتها.
- `tests/test_bfs.py`: التحقق من أمثلة الملفات، أقصر مسار، الدورات، والهدف غير المتاح.
- `BFS_Problem_Formulation.pdf`: شرح المسألة والخوارزمية والكود والواجهة.

لتجربة BFS في الطرفية فقط:

```bash
python bfs.py
```

لتشغيل الاختبارات، اختياريًا:

```bash
python -m pip install pytest
python -m pytest -q
```

## ملاحظات التحليل

الكود يعلّم الحالة وقت إضافتها للطابور ويفحص الهدف عند إخراجه، مثل المثال المحلول. الجيران يؤخذون بترتيب القوائم، ويمكن تحويل الترتيب إلى أبجدي من الواجهة.

في الجراف: BFS الأساسية زمنها `O(V + E)` وذاكرتها الإضافية `O(V)` بدون الجراف وسجل العرض. حفظ نسخة من الطابور والزيارة والاكتشاف في كل خطوة قد يرفع زمن التطبيق إلى `O(V + E + V²)` وذاكرة سجل الأنيميشن إلى `O(V²)`. عدد الحالات الأقصى داخل Queue ليس قياسًا للذاكرة بالبايت. الزمن الظاهر يشمل إنشاء سجل الخطوات ولا يشمل رسم الواجهة أو الانتظار بين الإطارات.

في تحليل شجرة البحث يذكر السكشن `O(b^d)` للوقت والذاكرة. مع اختبار الهدف عند إخراجه، قد نولّد بعض المستوى `d+1` قبل التوقف، فيكون الحد المحافظ `O(b^(d+1))`. BFS تضمن أقل عدد وصلات؛ ومع تكلفة موحدة 1 يكون ذلك أقل تكلفة أيضًا.
